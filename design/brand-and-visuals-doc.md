# SHIP BY SUNDAY

# Product Brand & Visual System Documentation

Version 1.0

Purpose of this document:

Provide the **visual system, brand rules, assets, and prompts** required to produce all graphics for the Ship by Sunday product.

This includes:

• website
• dashboard
• course materials
• marketing assets
• social content

---

# 1. Product Positioning

Ship by Sunday is **not a course**.

It is positioned as:

> **A system for shipping software.**

Messaging principle:

```
Idea → Live App
```

Everything in the visual language should reinforce:

```
precision
clarity
execution
builders shipping software
```

Avoid:

```
startup hype
AI magic marketing
stock imagery
generic course graphics
```

Brand tone should feel similar to:

• Linear
• Vercel
• Stripe docs
• Apple developer tools

---

# 2. Core Concept

The product teaches that **one builder can now perform the work of a full startup team using AI.**

The system is organized into **4 blocks**:

```
CEO → DESIGN → BUILD → SHIP
```

These blocks are the **core visual structure of the brand**.

They appear in:

• hero graphics
• curriculum sections
• social posts
• product dashboard
• course workbook
• slide decks

---

# 3. Signature Visual: The Shipping Pipeline

The primary brand artifact is the **shipping pipeline**.

Example structure:

```
IDEA
 ↓
DESIGN
 ↓
BUILD
 ↓
SHIP
 ↓
USERS
```

Simplified brand version:

```
CEO → DESIGN → BUILD → SHIP
```

Visual treatment:

• minimal system diagram
• thin lines
• node circles
• minimal icons

Example layout:

```
○──○──○──○
CEO  DESIGN  BUILD  SHIP
```

Accent color appears at the **final node**.

# 5. Color System

Primary palette:

```
#000000   black
#FFFFFF   white
#EAEAEA   light gray
```

Accent color:

```
#2D6CFF   electric blue
```

Usage rules:

Black/white dominate the design.

Blue is used only for:

• active states
• highlights
• links
• final nodes in pipelines

---

# 6. Typography

Headline font:

```
Suisse Intl
or
Inter Tight
```

Body font:

```
Inter
```

Style rules:

• large bold headlines
• minimal paragraph width
• generous spacing

Avoid decorative fonts.

---

# 7. Layout Language

Design should feel like **software modules**.

Example section block:

```
┌─────────────────────────┐
│  CEO BLOCK              │
│  Define the right idea  │
└─────────────────────────┘
```

Spacing should be **generous and structured**.

Avoid decorative shapes or gradients.

---

# 8. Product UI Language

Inside the product, everything should feel like **a builder console**.

Example UI block:

```
MISSION
Ship an app by Sunday
```

Progress display:

```
CEO        ✓
DESIGN     ✓
BUILD      ACTIVE
SHIP       LOCKED
```

Deployment example:

```
DEPLOYING...
```

Final state:

```
LIVE
```

centered subject
