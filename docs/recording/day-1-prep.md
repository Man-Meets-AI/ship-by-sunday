## Core example app

Use this as the main through-line for Day 1:

`Meeting Summary Tool`

Simple version:

- user pastes meeting notes
- app returns a short action summary
- user can review and share the summary

Why this is a good example:

- easy to explain
- believable
- scoped enough for the weekend
- fits the default teaching stack
- clean for problem, user, outcome, flow, and scope-cut examples

## 1. Weak idea vs stronger problem

### Weak idea

`I want to build an AI meeting app.`

Why it is weak:

- tool-first
- vague
- no user
- no pain
- no specific moment of use

### Stronger problem

`After team meetings, early-stage startup operators lose action items, forget decisions, and waste time turning messy notes into clear follow-up tasks.`

Why it is stronger:

- specific user
- specific moment
- real pain
- easy to imagine value

### Line to use

`Do not start with "I want to build an AI app." Start with "this person has this annoying problem in this moment."`

### 3 candidate problems to show on screen

Use this if you want to match the guide literally and show three candidate problems in a notes app:

1. `After team meetings, startup operators lose action items and waste time rewriting notes.`
2. `Freelancers forget client follow-ups because project notes are scattered across docs and chat threads.`
3. `Small teams lose track of recurring process tasks because nobody owns the checklist after the meeting ends.`

## 2. Blurry user vs tightened user

### Blurry user

`This app is for teams.`

### Better but still soft

`This app is for startup teams who have meetings.`

### Tightened user

`This app is for early-stage startup operators who run internal team meetings and need a faster way to turn messy notes into clear action items.`

### Sentence stem

`This app is for ___ who need ___ without ___.`

### Fill-in sentence

`This app is for early-stage startup operators who need to turn meeting notes into clear action items without manually rewriting everything after the call.`

### Line to use

`Not everyone. Not your whole market. One actual user in one actual moment.`

## 3. Feature-heavy statement vs outcome statement

### Feature-heavy version

`The app uses AI to summarize meetings, organize notes, and generate next steps.`

### Better outcome version

`The app helps startup operators leave a meeting with a clean action summary they can review and send in minutes.`

### Shortest version

`Turn messy meeting notes into a clear action summary in minutes.`

### Line to use

`People do not really want your feature list. They want the changed state on the other side of it.`

## 4. Simple research note grid

Use this if you want a clean example during `1.4 Light Research, Not a Thesis`.

### Reference notes

#### Competitor / reference 1

- does well: clean summary output
- does poorly: unclear task ownership
- users care about: speed and clarity

#### Competitor / reference 2

- does well: action items are easy to scan
- does poorly: too many features before the core use case
- users care about: being able to share the result fast

#### Competitor / reference 3

- does well: familiar note-taking pattern
- does poorly: output feels generic
- users care about: trustworthy summaries and less cleanup work

### Line to use

`You are not writing a market report. You are just trying not to build blind.`

## 5. Core flow example

Use this during `1.5 Map the Core Flow`.

### 5-step version

1. user pastes meeting notes
2. app generates a short action summary
3. user reviews and edits
4. user copies or shares the summary
5. team gets a clean follow-up record

### Messy vs clean flow

Messy flow:

`record meeting -> upload file -> transcribe audio -> identify speakers -> summarize notes -> generate tasks -> assign owners -> sync calendar -> send follow-up email -> track analytics`

Clean flow:

`paste notes -> generate summary -> review -> share -> done`

### Value moment

The value moment is:

`the user sees a clear, usable action summary without manually rewriting their notes`

### Line to use

`If you cannot explain the flow in a few steps, you are not ready to build it.`

## 6. Scope-cut example

Use this during `1.6 Kill Scope`.

### Original oversized idea

`AI meeting platform with recording upload, transcription, team workspaces, search, Slack integration, calendar sync, speaker recognition, follow-up emails, and analytics dashboard`

### Scope-cut to v1

`Paste meeting notes -> generate action summary -> review -> copy/share`

### Features to cut live

- recording upload
- calendar sync
- Slack integration
- team workspace
- analytics dashboard
- speaker recognition

### Sunday Test

Ask:

`What has to work by Sunday for the promise to still be true?`

For this example, the answer is:

`A user can paste notes, get a usable summary, and share it.`

### Line to use

`We are proving the promise, not shipping the full fantasy.`
