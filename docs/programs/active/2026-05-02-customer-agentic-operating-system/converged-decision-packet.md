# Converged Decision Packet

## Converged Direction

Ship by Sunday should become the agentic engineering operating system for both new generated repos and mature existing codebases.

For generated repos, the product should first reconcile the customer-safe source contract, then ship the operating system directly in the downloaded zip: generalized Program and ExecPlan contracts, folder indexes, templates, prompt assets, local skills, validation scripts, onboarding references, and an optional explicit bootstrap for the first Program packet.

For mature repos, the product should offer an adoption lane that audits the existing repository and returns an adoption Program plus the first child ExecPlan. That lane must be read-only until the customer reviews the proposed patch.

## Product Promise

The promise is not "AI will build your app." The promise is "your repo will know how to work with agents." That means durable source truth, scoped plans, validation loops, review evidence, and a way to resume work without chat memory.

## Boundaries

The first implementation slice belongs to generated customer repos only. It should reconcile source truth, prompt naming, skill trigger availability, snapshot boundaries, and validation promises before adding new operating-system artifacts. It should not build mature-repo ingestion, change checkout, change provider setup, change auth, change Convex runtime, change blueprint intake, or redesign the app.

The mature-repo lane should be designed in this Program before implementation starts. It likely requires separate slices for audit schema, local scanner or upload flow, adoption packet generation, product UI, and safe patch delivery.

## Durable Decisions

Use Program documents for multi-slice customer initiatives. Use ExecPlans for one bounded implementation slice. Keep Program planning briefs immutable. Require child ExecPlans to reference the exact versioned planning brief. Keep skills thin and docs-backed.

Do not use hidden `postinstall` generation. Use explicit commands and docs.

Do not ship internal `docs/programs/completed/**`, internal ExecPlans, local evidence, or historical transcripts to customers.

## Success Definition

The Program is complete when a generated customer repo can prove it contains the agentic operating pack and when Ship by Sunday has a durable mature-repo adoption path designed and implemented far enough that a customer with an existing repo can receive a usable adoption Program without greenfield assumptions.
