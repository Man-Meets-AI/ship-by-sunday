# Plan Split Recommendation

## Recommended Child ExecPlans

1. Reconcile Customer Agentic Source Contract.
   Align generated root guidance, Build Pack docs, prompt naming, skill triggers, snapshot boundaries, package-script promises, and tests before adding the full operating pack. Keep the work compiler-owned.

2. Ship Customer-Safe Operating System File Set.
   Add generalized Program and ExecPlan contracts, indexes, templates, prompt assets, skills, package scripts, and generated-repo tests. Keep internal archives excluded.

3. Add Explicit Generated Repo Agentic Bootstrap.
   Add an explicit command and guidance that creates or refreshes the first generated-repo Program packet from `docs/facts/project-definition.json`, `DESIGN.md`, and Build Pack readiness. Do not use `postinstall`.

4. Teach The Two-Lane Product Model.
   Update customer docs and product surfaces so users understand the difference between starting from a generated repo and upgrading an existing mature repo.

5. Design Mature Repo Audit Contract.
   Define the read-only audit inventory, maturity score, source-truth map, validation command map, and output schema for existing repos.

6. Generate Mature Repo Adoption Program.
   Create the artifact generator that returns an adoption Program, first child ExecPlan, and patch bundle without assuming the starter stack.

7. Wire Mature Repo Adoption Into The Product.
   Add the app flow only after the audit and artifact contracts are stable.

8. Harden Cross-Lane Review And Validation.
   Add replay fixtures, docs checks, customer-safety checks, and review prompts that prove both lanes stay honest.

## First Child ExecPlan

The first child ExecPlan is `docs/exec-plans/active/2026-05-02-reconcile-customer-agentic-source-contract.md`.

## Boundary Rules

The first child ExecPlan must not change auth, billing, checkout, Convex runtime, provider setup, blueprint intake schema, mature-repo upload flows, or public pricing.

The first child ExecPlan may update `packages/blueprint-compiler`, generated starter docs, generated starter skills, generated prompt wiring, customer-safe snapshot contracts, output tracing, and compiler tests. It should not add package scripts for validators until the validator implementation also ships.
