# Ship by Sunday Course Ops Plan

Last updated: 2026-03-10

## Objective

Turn the recorded lessons and existing assets into a student experience that feels simple, premium, and momentum-building from purchase through first completed rep.

The operating rule is simple: reduce ambiguity, reduce clicks, reduce worksheet clutter, and make the next action obvious at every step.

## Student-Facing Course Structure

### Start Here

Purpose: orient the student, install the working rules, and get them into motion fast.

Lessons:

1. Welcome to Ship by Sunday
2. How the Sprint Works

Current in-product mapping:

- `0.0` Mission Map
- `0.1` Welcome to Ship by Sunday
- `0.2` How the Sprint Works
- setup actions happen inside the Start Here lesson flow instead of as a third standalone lesson

Downloads:

- Student Packet
- Worksheet Packet

### Module 1: CEO Block

Purpose: choose the right problem, user, outcome, flow, and scope before building.

Lessons:

1. Start With the Problem
2. Pick One User
3. Define the Outcome
4. Light Research, Not a Thesis
5. Map the Core Flow
6. Kill Scope
7. CEO Block Wrap-Up

Core artifact:

- Worksheet 01: One-Page Product Brief

### Module 2: Design Block

Purpose: make the product buildable before code starts.

Lessons:

1. Find References First
2. Sketch Before Software
3. Storyboard the Journey
4. Figma Basics for Speed
5. Turn Sketches Into Rough Screens
6. Choose a Visual Direction
7. Design Block Wrap-Up

Core artifact:

- Worksheet 02: Build-Ready Design Spec

### Module 3: Build Block

Purpose: translate the brief into a working local v1 without chaos.

Lessons:

1. Build From the Brief
2. Set Up the Environment
3. Brief the Agent Correctly
4. Build the Core Flow
5. Debug Without Spiraling
6. Build Block Wrap-Up

Core artifact:

- Worksheet 03: Build Plan + Agent Brief

### Module 4: Ship Block

Purpose: get the app live, make the first send, and capture feedback.

Lessons:

1. Ship the Core, Not the Fantasy
2. Deploy the App
3. Record a Simple Demo
4. Send It to Real Humans
5. Capture Feedback and Plan Version Two
6. Final Wrap

Core artifact:

- Worksheet 04: Launch Plan + Feedback Tracker

## Recommended Student Navigation

Use this order in the product:

1. `Mission`
2. `Start Here`
3. `CEO Block`
4. `Design Block`
5. `Build Block`
6. `Ship Block`
7. `Artifacts`
8. `Settings`

Do not surface every file everywhere. Students should see the current module, the current worksheet, and the next action. Everything else can be one click away.

## Lesson Naming Conventions

Keep lesson titles short, directive, and parallel.

Module labels:

- `Start Here`
- `CEO Block`
- `Design Block`
- `Build Block`
- `Ship Block`

Lesson labels:

- Keep the lesson number visible
- Use title case
- Avoid extra punctuation

Recommended student-facing pattern:

- `1.1 Start With the Problem`
- `1.2 Pick One User`
- `1.3 Define the Outcome`

Download naming:

- `Friday Prep Sheet`
- `Worksheet 01: One-Page Product Brief`
- `Worksheet 02: Build-Ready Design Spec`
- `Worksheet 03: Build Plan + Agent Brief`
- `Worksheet 04: Launch Plan + Feedback Tracker`
- `Student Packet`

## Worksheet Audit

### Keep

- Friday Prep Sheet
- Worksheet 01: One-Page Product Brief
- Worksheet 02: Build-Ready Design Spec
- Worksheet 03: Build Plan + Agent Brief
- Worksheet 04: Launch Plan + Feedback Tracker
- Student Packet as the orientation / summary artifact

### Merge

- Merge any extra standalone worksheet prompts into the Student Packet or the four canonical worksheets
- Merge any weak duplicate prompts into lesson notes instead of shipping them as separate files

### Optional

- Extra example references
- Bonus checklists that do not block first completion
- Any polished examples that help confidence but are not required for momentum

### Remove From Day-One Student View

- Instructor Packet
- Facilitator Certification Rubric
- Any internal production documents
- Any extra worksheets not directly used in a lesson

### Worksheet rule

Ship only the four canonical worksheets plus the Student Packet on day one. Anything else increases friction unless it clearly helps completion.

## Support and Troubleshooting Outline

### Support categories

- login / access issue
- cannot find worksheet or download
- blocked in CEO Block
- blocked in Build Block
- deployment issue
- unsure where to go next

### Standard support responses to prepare

- where to start
- how to resume if stuck
- which worksheet to use
- what to do if the app is too ambitious
- how to reduce scope and keep moving

### Support flow

1. confirm which block the student is in
2. confirm which artifact they have completed
3. reduce the problem to one next step
4. route technical failures separately from motivation failures

## Founder Dependencies

- founder recordings must follow the agreed lesson order
- final approval if lesson names change materially
- any example app that becomes the canonical student demo

## Launch Recommendation

Ship the simplest clean student experience first:

- 4 blocks
- 4 worksheets
- 1 Start Here path
- 1 support path

Do not ship a library. Ship a guided rep.
