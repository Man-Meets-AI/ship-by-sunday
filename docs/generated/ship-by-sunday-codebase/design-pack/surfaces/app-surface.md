# App Surface Rules

Use this sheet for product surfaces, workspaces, and operational UI.

## Core defaults

- Default to calm hierarchy, strong typography, sparse color, and minimal chrome.
- Organize around a primary workspace, navigation, secondary context, and one clear accent for action or state.
- Use utility copy instead of marketing copy.
- Start with the working surface itself, not a homepage-style hero.
- Do not introduce a hero section unless it was explicitly requested.

## Layout

- If a panel can become plain layout without losing meaning, remove the card treatment.
- If a section does not help someone operate, monitor, or decide, remove it.
- Use cards only when they are the interaction container or clearly improve comprehension.
- Keep headings operational: say what the user can see, do, or change.

## Copy

- Headings should describe the surface, status, or action.
- Supporting copy should explain scope, behavior, freshness, or decision value in one short sentence.
- Avoid marketing language unless the surface is truly promotional.
- Avoid wispy all-caps eyebrow labels and other decorative micro-labels; prefer sentence-case operational labels that explain what the user can do or see.

## Interaction

- Favor progressive disclosure when the surface has multiple levels of detail.
- Make every interactive surface feel intentional and responsive.
- Keep primary actions obvious and secondary actions visually quieter.

## Exceptions

- If a hero is necessary in an app surface, document the reason and keep it narrow.
- If cards are required for scanning or grouping, use them sparingly and keep the hierarchy calm.
