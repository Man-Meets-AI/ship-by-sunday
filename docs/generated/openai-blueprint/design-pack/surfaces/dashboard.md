# Dashboard Rules

Use this sheet for dashboards and metric-heavy surfaces.

## Core defaults

- Build for scanning first.
- Put the primary question, KPI, or decision at the top of each region.
- Keep the hierarchy calm: strong typography, sparse color, and minimal chrome.
- Use cards only when grouping improves scanability or comparison.

## Layout

- Prefer stable rows, columns, and panels that make comparisons easy.
- Keep filters, dates, and status controls easy to find.
- Avoid decorative gradients, marketing-style hero blocks, and oversized promotional copy.
- If a section can become plain layout without losing meaning, remove the card treatment.

## Copy

- Headings should name the metric, process, or decision.
- Supporting copy should tell the user what changed, why it matters, or what to do next.
- Use utility language, not promotional language.

## Data and motion

- Charts, tables, and KPIs should share a coherent visual rhythm.
- Motion should clarify change, loading, or drilldown state.
- Avoid ornamental motion, sparkles, and unnecessary flourish.

## Exceptions

- If a dashboard needs a branded top section, keep it minimal and subordinate to the work surface.
- If a chart card needs stronger framing for comprehension, document why in the plan.
