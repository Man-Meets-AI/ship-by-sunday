# Route Map

## Public routes

- `/`: public marketing surface
- `/docs`: public builder docs
- `/sign-in`: Clerk sign-in
- `/sign-up`: Clerk sign-up

## Purchase and recovery routes

- `/checkout/success`: post-checkout validation, server-fetched initial product-access state, then live product-access polling
- `/checkout/cancel`: checkout cancel return
- `/mission`: canonical workspace entry and recovery destination

## Protected product routes

- `/mission`: main protected home and resume target
- `/lesson/[lessonId]`: protected lesson flow
- `/artifacts`: saved student or product artifacts
- `/settings`: protected account and product settings

These protected routes render behind `app/(workspace)/layout.tsx`, starting from server-fetched access or mission data before the browser resumes live Convex subscriptions.

## Why this matters

If you use the wrong route language in prompts or docs, the agent can implement the right idea against the wrong surface.
