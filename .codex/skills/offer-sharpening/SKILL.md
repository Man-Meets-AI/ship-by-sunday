# Offer Sharpening

Use this skill when an offer feels generic, too broad, hard to explain, weakly differentiated, or commercially soft.

This is a Man Meets AI workspace skill. It is meant to sharpen offer logic first, then produce bounded rewrite-ready messaging. It is not a full-page copywriting skill.

## Read Order

Read inputs in this order:

1. The current offer doc, landing-page copy, checkout copy, or notes the user wants sharpened.
2. [docs/offer-funnel/messaging-foundation.md](../../../docs/offer-funnel/messaging-foundation.md) if it exists and is relevant.
3. These research docs as the reasoning framework:
   - [docs/offer-funnel/research/brand/iman-personal-brand-research-notes.md](../../../docs/offer-funnel/research/brand/iman-personal-brand-research-notes.md)
   - [docs/offer-funnel/research/brand/iman-personal-brand-transcript.md](../../../docs/offer-funnel/research/brand/iman-personal-brand-transcript.md)
   - [docs/offer-funnel/research/2026-03-11-iman-gadzhi-80-20-marketing-sales-transcript.md](../../../docs/offer-funnel/research/2026-03-11-iman-gadzhi-80-20-marketing-sales-transcript.md)
4. Any new transcript, research notes, or positioning memo included in the current task. Treat these as additive evidence, not proof for public claims.

## Core Rules

- Identify the real buyer before touching the copy.
- Diagnose buyer sophistication. Do not talk to beginners, mid-market complexity seekers, and advanced buyers in the same voice.
- Bias toward beginner-clear language even when the buyer is technical.
- Sell a better process, not generic information, coaching, access, or vibes.
- Force a named mechanism or process that explains why this offer works.
- Make the mechanism easy to explain to an outsider.
- Use the mechanism to explain why the buyer keeps getting stuck.
- Assume every mechanism creates new limiting beliefs. Surface them early.
- Keep the core offer clean. Use bonuses to reduce fear and neutralize objections without bloating the main thing.
- Separate founder-brand work from company-brand work.
- Optimize for the right buyer recognizing themselves, not for broad reach or sounding impressive.
- Do not force `The Product Trinity` or any existing Man Meets AI language unless the current input actually supports it.

## Default Workflow

1. Diagnose the current offer:
   - What is being sold?
   - Who is it for?
   - What feels generic, muddy, or commercially weak?
2. Identify the real buyer and their sophistication level:
   - beginner-clear
   - mid-market complexity-seeking
   - advanced / direct
3. Translate the current offer into plain outsider language. If a non-expert would not understand it fast, simplify it.
4. Generate 3-5 named mechanism options.
5. Pressure-test each mechanism:
   - clear
   - ownable
   - specific
   - relevant to the stuck point
   - not empty jargon
6. Recommend one mechanism and explain why it is the strongest fit.
7. Explain why the buyer is stuck without this mechanism.
8. List the limiting beliefs the mechanism creates.
9. Map each limiting belief to a counter:
   - core offer structure
   - proof requirement
   - objection handling
   - bonus
   - packaging / framing
10. Separate what belongs in founder-brand messaging versus company-brand messaging.
11. Produce bounded rewrite-ready positioning.

## Output Contract

Default output sections:

1. `Offer Snapshot`
2. `Buyer + Sophistication Diagnosis`
3. `Plain-English Translation`
4. `Mechanism Options`
5. `Recommended Mechanism`
6. `Why The Buyer Is Stuck`
7. `Limiting Beliefs + Counters`
8. `Core Offer vs Bonus Role`
9. `Founder Brand vs Company Brand`
10. `Sharpened Positioning Lines`
11. `Open Questions`

Inside `Sharpened Positioning Lines`, include only bounded rewrite-ready assets:

- one-sentence offer
- short promise
- one mechanism paragraph
- one stuck-point explanation
- 3 objection answers
- one bonus-positioning line
- 3-5 message angles

## Guardrails

- Do not use creator transcripts as proof for Man Meets AI sales claims.
- Do not invent proof, testimonials, stats, or outcomes.
- Do not jump straight into full-page drafting unless the user explicitly asks for it after positioning is locked.
- If the task becomes page copy, hand off to `copywriting`.
- If the task becomes line editing on existing copy, hand off to `copy-editing`.
- Keep the mechanism stable once recommended. Do not rename it repeatedly inside one deliverable.
- If existing offer docs already contain strong language, sharpen and reuse it instead of rewriting for novelty.

## Good Uses

- "Sharpen this offer."
- "Make this positioning less generic."
- "Find the unique mechanism."
- "Name the process behind this offer."
- "Map the objections and bonuses."
- "Separate founder brand from company brand in this messaging."

## Bad Uses

- "Rewrite my whole landing page" when the offer logic has not been diagnosed yet.
- "Proofread this paragraph" when the job is line editing, not offer strategy.
- "Invent testimonials" or "make up proof."
