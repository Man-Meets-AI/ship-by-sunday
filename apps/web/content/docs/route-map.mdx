# Route Map

## Public routes

- `/`: public marketing surface
- `/docs`: public builder docs when the docs module is enabled; disabled-state surface when it is off
- `/blog`: public editorial index plus `/blog/<slug>` article routes for published posts
- `/sign-in`: branded starter-owned Clerk sign-in surface
- `/sign-up`: pricing redirect; legacy checkout session links forward to checkout email handoff

## Purchase and recovery routes

- `/checkout/success`: post-checkout validation, server-fetched initial product-access state, then live product-access polling
- `/checkout/email-handoff`: locked checkout-email Clerk code flow after paid guest checkout; validates and fulfills the Stripe session before showing the email-code form
- `/checkout/clear-pending`: route-handler-only stale pending-checkout cookie cleanup, then safe redirect
- `/checkout/cancel`: checkout cancel return; redirects through pending-cookie cleanup
- `/checkout/cancel/confirmed`: checkout canceled confirmation surface
- `/session-tasks/reset-password`: Clerk password-reset task inside the shared identity shell
- `/codebase`: generated-codebase protected landing after checkout or sign-in when checkout intent resolves to `generated_codebase`
- `/workspace/choose`: protected legacy-intent choice screen for paid checkouts that predate checkout intent metadata
- `/workspace/setup`: existing-codebase protected setup console when checkout intent resolves to `existing_codebase_doctor`
- `/tutorials`: protected Tutorial Videos library for paid customers who want to watch without choosing or changing a product path
- `/mission`: protected compatibility entry for the post-review Lesson Map; it stays locked until Review unlocks the post-review branch

## Protected product routes

- `/codebase`: generated-codebase workspace with the overview block plus the `foundation`, `problem`, `outcome`, `design`, `pricing`, `setup`, and `generated-preview` sections
- `/workspace/choose`: protected fulfillment choice for missing or legacy checkout intent; saves the selected fulfillment track before redirecting
- `/workspace/setup`: existing-codebase setup console for local runner pairing, Machine Setup readiness, Project Setup readiness, privacy defaults, default open destination, and doctor-pass readiness
- `/workspace/doctor-pass`: planned existing-codebase doctor-pass progress route after setup; it must not stream raw terminal logs by default
- `/workspace/findings`: planned Top 9 findings ledger after the doctor pass sync preview is approved
- `/workspace/findings/[findingId]`: planned finding decision route for approving one concrete workflow
- `/workspace/loops`: planned finding-filtered workflow catalog; not an always-on queue in Crawl
- `/workspace/runs`: planned doctor-pass and approved-workflow run history; no queue controls in Crawl
- `/workspace/privacy`: planned local-execution and sync-boundary controls for runner revocation and report deletion
- `/review`: customer-facing `Review` handoff; it makes one auto-download attempt for the Ship by Sunday Codebase, then keeps the fallback download link visible if the browser blocks the download
- `/tutorials`: protected Tutorial Videos index; available to paid customers across generated-codebase, existing-codebase, and unresolved product paths
- `/tutorials/[lessonKey]`: protected video-first tutorial watch page; uses the same lesson video content as the post-review lesson flow without generated-codebase unlock or progress state
- `/settings`: protected account and product settings
- `/lesson/[lessonKey]`: canonical post-review lesson route; renders locked messaging before unlock and video-first lessons after unlock

## Protected compatibility routes

- `/execute`: compatibility route for old Execute / Ship links; before post-review unlock it redirects to `/review`, and after unlock it redirects to the canonical Build Lessons destination
- `/mission`: compatibility route for old bonus-library links; before post-review unlock it renders Review guidance, and after unlock it redirects to the Review Lesson Map at `/review?showLessonMap=1`
- `/artifacts`: legacy compatibility route that now forwards into `/review`
- `/start`: compatibility redirect to `/codebase`
- `/product`, `/product/[stepId]`, `/design`, `/design/[stepId]`, `/marketing`, `/marketing/[stepId]`, `/build-plan`, `/build-plan/[stepId]`: compatibility redirects to the matching `/codebase#<section>` anchor; `/marketing/operating-system` redirects to `/codebase#generated-preview`

Repeat-routing note: `/execute` does not render a bridge page. Review owns the post-download continue action, `/execute` preserves old links by sending unlocked members into Build Lessons, and `/mission` preserves old library links by sending unlocked members into the Review Lesson Map.

These protected routes render behind `app/(workspace)/layout.tsx`, starting from server-fetched access or codebase-workspace data before the browser resumes live Convex subscriptions. The canonical intake is now one `/codebase` page plus customer-facing `Review`; the old staged URLs survive only as compatibility redirects.

## Why this matters

If you use the wrong route language in prompts or docs, the agent can implement the right idea against the wrong surface.
