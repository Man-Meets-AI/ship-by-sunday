# Environment Variables

Use `apps/web/.env.local.example` as the tracked contract for the local web app.

Run `bun run dev:convex` to connect the repo to your hosted Convex dev deployment. That command writes `NEXT_PUBLIC_CONVEX_URL` and `CONVEX_DEPLOYMENT` into `apps/web/.env.local`.

## Core public runtime

- `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`: lets the browser talk to Clerk
- `NEXT_PUBLIC_CLERK_SIGN_IN_URL`: must stay `/sign-in` because the app uses a custom Clerk sign-in route
- `NEXT_PUBLIC_CONVEX_URL`: lets the browser talk to Convex
- `NEXT_PUBLIC_CONVEX_SITE_URL`: optional but important for Convex HTTP actions like observability ingest and incident status control when the deployment serves browser traffic on `.convex.cloud` and HTTP actions on `.convex.site`

## Convex CLI target

- `CONVEX_DEPLOYMENT`: written by `convex dev` into `apps/web/.env.local` so repo scripts and `convex run` commands target your hosted Convex dev deployment explicitly

## Core server runtime

- `APP_BASE_URL`: canonical app URL for checkout success and cancel redirects
- `CLERK_AUTHORIZED_PARTIES`: optional comma-separated origin allowlist passed to Clerk middleware for subdomain cookie-leak protection
- `CLERK_SECRET_KEY`: server-side Clerk access
- `CLERK_FRONTEND_API_URL`: Clerk frontend API domain used by the auth chain
- `CLERK_WEBHOOK_SIGNING_SECRET`: verifies Clerk webhook requests sent to `/api/observability/clerk`
- `OBSERVABILITY_INGEST_TOKEN`: shared random secret used by Next.js to authenticate error-ingest requests into Convex
- `OBSERVABILITY_INCIDENT_CONTROL_TOKEN`: separate bearer token for the maintainer-only incident status route at `/api/observability/incidents/[incidentId]/status`
- `OBSERVABILITY_VERCEL_WEBHOOK_SECRET`: verifies Vercel deployment webhooks sent to `/api/observability/vercel`
- `STRIPE_SECRET_KEY`: Stripe API access
- `STRIPE_PUBLISHABLE_KEY`: safe-to-expose Stripe key used by homepage Express Checkout
- `STRIPE_WEBHOOK_SECRET`: verifies the Stripe webhook
- `STRIPE_PRICE_ID`: optional dashboard-managed price; leave it unset locally until your test account has a managed `$500` price that matches the live list-price contract
- `STRIPE_PRODUCT_ID`: optional product id emitted by the Stripe script
- `STRIPE_PROMOTION_CODE_ID`: required when the active public pricing offer is auto-applied at checkout; use the Stripe promotion-code ID, not the customer-facing code string

With the current early-member pricing slice, the app truth is a `$500` list price plus a `50%` auto-applied offer. That means local/test Stripe parity now has two moving parts: a matching `$500` test price and a matching test promotion code. Until those assets exist in the test account, keep `STRIPE_PRICE_ID` unset locally so checkout uses inline `price_data`, and do not hard-code a guessed public code name like `EARLYSHIP` into repo config. The repo consumes Stripe resource IDs and lets dashboard state own the customer-facing code string.

Stripe guest purchase fulfillment runs inside Convex and calls Clerk by checkout email. Keep `CLERK_SECRET_KEY`, `STRIPE_SECRET_KEY`, and `STRIPE_WEBHOOK_SECRET` synced into the active Convex deployment as well as the Next.js runtime.

## PostHog and Telegram observability

- `NEXT_PUBLIC_POSTHOG_TOKEN`: public PostHog project token used by browser analytics; it starts with `phc_`
- `NEXT_PUBLIC_POSTHOG_HOST`: PostHog browser ingest host; US Cloud uses `https://us.i.posthog.com`
- `POSTHOG_PROJECT_ID`: numeric PostHog project id used by source-map upload tooling
- `POSTHOG_API_KEY`: secret PostHog personal API key used only for source-map uploads; create it as a project-scoped key with only the `Source map upload` scope
- `TELEGRAM_BOT_TOKEN`: Telegram bot token used for production alerts
- `TELEGRAM_CHAT_ID`: chat or group id that receives alerts
- `ENABLE_OBSERVABILITY_TEST_TRIGGER`: test-only switch for the Playwright protected-shell failure harness
- `CHECKOUT_SUCCESS_FIXTURES`: test-only switch that enables the `/checkout/success?fixture=<variant>` deterministic in-memory fixture for capturing the polling -> redirect-armed arc in a real browser. The fixture refuses to activate unless this is set to `1` AND `NODE_ENV !== "production"`. Leave unset outside local development and CI screenshot capture; never set it on a production deployment

`OBSERVABILITY_INGEST_TOKEN` is a high-entropy shared secret between the Next.js app and Convex. In production, keep `NEXT_PUBLIC_CONVEX_SITE_URL` aligned with the live Convex HTTP-actions host so observability and other HTTP-action traffic do not fall back to the browser-only client origin.

`POSTHOG_API_KEY` is not the browser project token and must not use all-access permissions. Use a separate personal API key for MCP or agent tooling if OAuth is unavailable.

`NEXT_PUBLIC_POSTHOG_TOKEN` and `NEXT_PUBLIC_POSTHOG_HOST` are validated as a pair. Set both to enable browser analytics, error tracking, and masked session replay, or leave both unset. `POSTHOG_PROJECT_ID` and `POSTHOG_API_KEY` are production-build values for source-map upload only; do not expose the personal API key through a `NEXT_PUBLIC_` variable.

PostHog MCP is an operator setup, not an app env variable. Prefer OAuth through the PostHog AI plugin. If OAuth is unavailable, create a separate project-scoped Personal API Key with only the `MCP Server` scope.

- `CLERK_TEST_USER_SCOPE`

## Practical rule

Only set what the current flow actually needs. The app does not require every optional variable on day one.
