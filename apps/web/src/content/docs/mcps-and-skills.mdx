# MCPs and Skills

MCPs and skills solve two different problems:

- MCPs give the agent tools or external-system access
- skills give the agent sharper instructions for a specific provider or workflow

## Good first MCPs

- `Figma` for design context and design-to-code work
- `Playwright` for browser QA and clicking real flows
- `PostHog` for analytics, error tracking, session replays, source-map evidence, and SDK Doctor checks

## Good first skills

- `Clerk` for authentication work
- `Convex` for app data and product-access work
- `PostHog to Linear triage` for draft-only bug review from PostHog evidence into Linear issue bodies
- `Stripe` for checkout and webhook work
- any repo-local docs, QA, or workflow skills the project already maintains

## When to use them

- use a provider skill when the problem is provider-specific
- use Playwright when the answer depends on what actually happens in the browser
- use Figma when the design file is the source of truth
- use PostHog when the answer depends on product events, frontend errors, session replays, or release-specific stack traces
- do not invoke everything at once just because it exists

## PostHog capability setup

PostHog has two separate credential paths:

- Source-map uploads use a project-scoped personal API key with `Source map upload` access only.
- Agent investigation uses the PostHog MCP or PostHog AI plugin. Prefer OAuth or a separate project-scoped key with only the access needed for analytics queries, error review, replay links, SDK Doctor, and MCP server access.

For Vercel-backed customer projects, configure these environment variables in production, preview, and development:

- `NEXT_PUBLIC_POSTHOG_TOKEN`
- `NEXT_PUBLIC_POSTHOG_HOST`
- `POSTHOG_PROJECT_ID`
- `POSTHOG_API_KEY`

Keep `POSTHOG_PROJECT_ID` and `POSTHOG_API_KEY` encrypted or secret in hosted environments. The public PostHog token and host can be public client configuration.

The Codex PostHog AI plugin can be installed with:

```sh
codex plugin marketplace add PostHog/ai-plugin
```

After installing the plugin, restart the agent session if the PostHog MCP tools are not visible yet.

## PostHog to Linear triage

PostHog-backed triage starts draft-only. The agent should collect PostHog issue URLs, safe replay links, source-mapped stack frames, affected users and sessions, release context, duplicate Linear or GitHub candidates, and a P0-P3 severity recommendation before creating or changing anything in Linear.

Telegram is only a notification surface. Use it for high-signal alerts or daily summaries, not as the system of record. PostHog remains the evidence source and Linear remains the durable bug tracker.

## Practical rule

The more specific the tool or skill, the more specific your prompt should be. Ask for one concrete outcome, not a vague “handle this whole app.”

## What success looks like

You are using MCPs and skills well when the agent has the minimum extra capability needed to solve the current problem cleanly.
