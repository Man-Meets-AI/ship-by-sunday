# Environment Variables

Use `apps/web/.env.local.example` as the tracked contract for the local web app.

Run `bun run dev:convex` to connect the repo to your hosted Convex dev deployment. That command writes `NEXT_PUBLIC_CONVEX_URL` and `CONVEX_DEPLOYMENT` into `apps/web/.env.local`.

## Core public runtime

- `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`: lets the browser talk to Clerk
- `NEXT_PUBLIC_CLERK_SIGN_IN_URL`: must stay `/sign-in` because the app uses a custom Clerk sign-in route
- `NEXT_PUBLIC_CONVEX_URL`: lets the browser talk to Convex
- `NEXT_PUBLIC_CONVEX_SITE_URL`: optional but important for Convex HTTP actions like observability ingest and incident status control when the deployment serves browser traffic on `.convex.cloud` and HTTP actions on `.convex.site`

## Convex CLI target

- `CONVEX_DEPLOYMENT`: written by `convex dev` into `apps/web/.env.local` so repo scripts and `convex run` commands target your hosted Convex dev deployment explicitly

## Core server runtime

- `APP_BASE_URL`: canonical app URL fallback when no trusted request origin is available; request-scoped route handlers such as checkout use the incoming buyer origin for success and cancel redirects only when it matches `APP_BASE_URL`, `VERCEL_BRANCH_URL`, `VERCEL_URL`, `VERCEL_PROJECT_PRODUCTION_URL`, or a local development origin
- `CLERK_AUTHORIZED_PARTIES`: optional comma-separated origin allowlist passed to Clerk middleware for subdomain cookie-leak protection
- `CLERK_SECRET_KEY`: server-side Clerk access
- `CLERK_FRONTEND_API_URL`: Clerk frontend API domain used by the auth chain
- `CLERK_WEBHOOK_SIGNING_SECRET`: verifies Clerk webhook requests sent to `/api/observability/clerk`
- `OBSERVABILITY_INGEST_TOKEN`: shared random secret used by Next.js to authenticate error-ingest requests into Convex
- `OBSERVABILITY_INCIDENT_CONTROL_TOKEN`: separate bearer token for the maintainer-only incident status route at `/api/observability/incidents/[incidentId]/status`
- `OBSERVABILITY_VERCEL_WEBHOOK_SECRET`: verifies Vercel deployment webhooks sent to `/api/observability/vercel`
- `STRIPE_SECRET_KEY`: Stripe API access
- `STRIPE_PUBLISHABLE_KEY`: safe-to-expose Stripe key used by homepage Express Checkout
- `STRIPE_WEBHOOK_SECRET`: verifies Stripe webhook signatures at `/api/stripe/webhook`
- `CAL_WEBHOOK_SECRET`: verifies Cal.com webhook signatures at `/api/cal/worker-seal-team-6/webhook`
- `CONVEX_WEBHOOK_MUTATION_SECRET`: server-only shared secret used by trusted Next.js routes to write billing sync state into Convex; use at least 32 random characters and mirror the same value into the matching Convex deployment
- `CHECKOUT_FULFILLMENT_RETRY_SECRET`: server-only shared secret used by Next.js and Convex when checkout API routes create purchase-intent records and when `/checkout/success` retries paid-session fulfillment while webhook delivery catches up; use at least 32 random characters and mirror the same value into the matching Convex deployment
- `STRIPE_STARTER_PRICE_ID`: dashboard-managed Starter price for the `$297` Starter offer; optional locally because checkout falls back to inline `price_data`, required for hosted preview and production billing proof
- `STRIPE_STARTER_PRODUCT_ID`: Starter product id emitted by the Stripe product script; optional locally, used by release proof when present
- `STRIPE_WORKERS_PRICE_ID`: dashboard-managed Workers price for the `$600` Workers offer; optional locally because checkout falls back to inline `price_data`, required for hosted preview and production billing proof
- `STRIPE_WORKERS_PRODUCT_ID`: Workers product id emitted by the Stripe product script; optional locally, used by release proof when present
- `STRIPE_PRICE_ID` and `STRIPE_PRODUCT_ID`: legacy Starter fallback env vars kept so existing local setups do not break immediately; prefer the offer-specific env vars above
- `STRIPE_PROMOTION_CODE_ID`: deprecated; new Starter and Workers checkout sessions do not auto-apply a shared promotion code

The app now has two checkout offers. Starter grants generator and lesson access, sends successful buyers to `/starter/home`, and charges `$297` through a one-time price. Workers grants Worker access only, sends successful buyers to `/workers/setup`, and charges `$600` through a recurring subscription price. Create one Stripe product and one matching price for each offer in every Stripe mode you test. Store the IDs in `.env.local`, Vercel, and any release-proof environment that runs hosted billing checks. Local checkout can run without price IDs because it uses inline price data, but hosted preview and production proof require managed price IDs for both offers.

Stripe webhook verification now runs in the Next.js app route, then trusted billing writes cross into Convex through `CONVEX_WEBHOOK_MUTATION_SECRET`. Keep `CLERK_SECRET_KEY`, `STRIPE_SECRET_KEY`, `CONVEX_WEBHOOK_MUTATION_SECRET`, and `CHECKOUT_FULFILLMENT_RETRY_SECRET` synced into the active Convex deployment as well as the Next.js runtime where applicable. Keep `STRIPE_WEBHOOK_SECRET` in the Next.js runtime for `/api/stripe/webhook`; only mirror it into Convex if you deliberately use the legacy `/stripe/webhook` compatibility endpoint. If `STRIPE_WEBHOOK_SECRET` is missing or mismatched, the app route cannot verify Stripe events. If `CONVEX_WEBHOOK_MUTATION_SECRET` is missing or mismatched, verified webhook events cannot write billing state into Convex. If `CHECKOUT_FULFILLMENT_RETRY_SECRET` is missing, too short, or mismatched, checkout cannot write the protected purchase-intent ledger and the checkout success page cannot safely trigger the same server-side fulfillment retry.

## Worker Seal Team 6 Cal.com

- `NEXT_PUBLIC_WORKER_SEAL_TEAM_6_CAL_LINK`: public Cal Link slug or full hosted URL for the Worker Seal Team 6 booking page. When it is unset, `/worker-seal-team-6` shows the direct scheduling fallback instead of injecting Cal.com's embed script.
- `NEXT_PUBLIC_WORKER_SEAL_TEAM_6_CAL_ORIGIN`: optional Cal.com origin for the embed and hosted fallback link. Defaults to `https://cal.com`.
- `CAL_WEBHOOK_SECRET`: server-only Cal.com webhook signing secret for `POST /api/cal/worker-seal-team-6/webhook`.

Create the Cal.com event type as `Worker Seal Team 6`, set it to 60 minutes and `$500 USD`, connect the Cal.com Stripe app, and subscribe the webhook endpoint to `BOOKING_CREATED`, `BOOKING_PAYMENT_INITIATED`, `BOOKING_PAID`, `BOOKING_RESCHEDULED`, and `BOOKING_CANCELLED`. Store the public link in `.env.local` and Vercel env. Store `CAL_WEBHOOK_SECRET` only in the Next.js runtime. Keep `CONVEX_WEBHOOK_MUTATION_SECRET` mirrored into both Next.js and hosted Convex, because verified Cal.com events use that secret-gated boundary to write booking mirror state into Convex.

See [Worker Seal Team 6 Cal.com](/docs/worker-seal-team-6-cal-com) for the full provider setup and verification steps.

## PostHog and Telegram observability

- `NEXT_PUBLIC_POSTHOG_TOKEN`: public PostHog project token used by browser analytics; it starts with `phc_`
- `NEXT_PUBLIC_POSTHOG_HOST`: PostHog browser ingest host; US Cloud uses `https://us.i.posthog.com`
- `POSTHOG_PROJECT_ID`: numeric PostHog project id used by source-map upload tooling
- `POSTHOG_API_KEY`: secret PostHog personal API key used only for source-map uploads; create it as a project-scoped key with only the `Source map upload` scope
- `TELEGRAM_BOT_TOKEN`: Telegram bot token used for production alerts
- `TELEGRAM_CHAT_ID`: chat or group id that receives alerts
- `ENABLE_OBSERVABILITY_TEST_TRIGGER`: test-only switch for the Playwright protected-shell failure harness
- `CHECKOUT_SUCCESS_FIXTURES`: test-only switch that enables the `/checkout/success?fixture=<variant>` deterministic in-memory fixture for capturing the polling -> redirect-armed arc in a real browser. The fixture refuses to activate unless this is set to `1` AND `NODE_ENV !== "production"`. When a `fixture` query is present but the switch is disabled or the slug is invalid, `/checkout/success` returns the normal not-found surface instead of falling through to a customer recovery state. Leave unset outside local development and CI screenshot capture; never set it on a production deployment

## Telegram support bot

These values live in the hosted Convex deployment because the support webhook and Telegram delivery run inside Convex:

- `TELEGRAM_SUPPORT_BOT_TOKEN`: dedicated Telegram bot token for homepage support
- `TELEGRAM_SUPPORT_CHAT_ID`: dedicated support supergroup id, usually `-100...`
- `TELEGRAM_SUPPORT_OPERATOR_USER_IDS`: comma-separated Telegram user ids allowed to reply or close support threads
- `TELEGRAM_SUPPORT_WEBHOOK_SECRET`: shared Telegram webhook secret; use the same value as `setWebhook.secret_token`
- `TELEGRAM_SUPPORT_ADMIN_RECOVERY_TOKEN`: maintainer-only token for retrying failed support deliveries
- `OPENAI_API_KEY`: OpenAI key used by Convex for private support draft generation
- `SUPPORT_AI_DRAFT_MODEL`: optional OpenAI model override for private support drafts; defaults to `gpt-5.4-mini-2026-03-17`
- `SUPPORT_CHAT_DISABLED`: optional kill switch; set to `1` or `true` to make the widget fall back to direct Telegram

See [Telegram Support Bot](/docs/telegram-support-bot) for the webhook command, exact Telegram permission names, AI draft setup, and verification steps.

`OBSERVABILITY_INGEST_TOKEN` is a high-entropy shared secret between the Next.js app and Convex. In production, keep `NEXT_PUBLIC_CONVEX_SITE_URL` aligned with the live Convex HTTP-actions host so observability and other HTTP-action traffic do not fall back to the browser-only client origin.

`POSTHOG_API_KEY` is not the browser project token and must not use all-access permissions. Use a separate personal API key for MCP or agent tooling if OAuth is unavailable.

`NEXT_PUBLIC_POSTHOG_TOKEN` and `NEXT_PUBLIC_POSTHOG_HOST` are validated as a pair. Set both to enable browser analytics, error tracking, and masked session replay, or leave both unset. `POSTHOG_PROJECT_ID` and `POSTHOG_API_KEY` are production-build values for source-map upload only; set both to enable upload, or omit either one to build without source-map upload. Do not expose the personal API key through a `NEXT_PUBLIC_` variable.

PostHog MCP is an operator setup, not an app env variable. Prefer OAuth through the PostHog AI plugin. If OAuth is unavailable, create a separate project-scoped Personal API Key with only the `MCP Server` scope.
