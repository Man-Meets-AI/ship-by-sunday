# Route Map

## Public routes

- `/`: public marketing surface
- `/starter`: public Starter sales page for the `$297` idea-to-repo offer
- `/workers`: public Workers sales page for the `$600` existing-codebase worker install
- `/docs`: public builder docs when the docs module is enabled; disabled-state surface when it is off
- `/blog`: public editorial index plus `/blog/<slug>` article routes for published posts
- `/sign-in`: branded starter-owned Clerk sign-in surface
- `/sign-up`: Starter redirect; legacy checkout session links forward back to checkout success

## Purchase and recovery routes

- `/checkout/success`: transient post-checkout fulfillment and validation route; it retries the webhook fulfillment path and sends signed-out paid buyers to normal passwordless sign-in
- `/checkout/clear-pending`: stale pending-checkout recovery screen that posts to `/checkout/clear-pending/submit` for cookie cleanup, then safe redirect
- `/checkout/cancel`: checkout cancel return; redirects through pending-cookie cleanup
- `/checkout/cancel/confirmed`: checkout canceled confirmation surface
- `/session-tasks/reset-password`: Clerk password-reset task inside the shared identity shell
- `/home`: protected paid product recovery hub for multi-product and legacy broad-access buyers
- `/starter/home`: first paid Starter destination after checkout; lets the buyer choose customized repo generation or template plus lessons
- `/starter/generate-codebase`: generated-codebase protected landing for new-idea work
- `/workers/setup`: Worker setup console for installing the local worker against an existing codebase
- `/starter/lessons`: protected Starter lesson library
- `/mission`: protected compatibility entry for the post-review Lesson Map; it stays locked until Review unlocks the post-review branch

## Protected product routes

- `/starter/home`: protected Starter hub for the guided-question generator path and the template plus guided-videos path
- `/starter/generate-codebase`: generated-codebase workspace with the overview block plus the `foundation`, `problem`, `outcome`, `design`, `pricing`, `setup`, and `generated-preview` sections
- `/home`: protected paid app hub for first-purchase welcome, cross-surface navigation, and returning-user app entry
- `/workers/setup`: existing-codebase setup console for local runner pairing, Machine Setup readiness, Project Setup readiness, privacy defaults, default open destination, and doctor-pass readiness
- `/workers/doctor-pass`: planned existing-codebase doctor-pass progress route after setup; it must not stream raw terminal logs by default
- `/workers/findings`: planned Top 9 findings ledger after the doctor pass sync preview is approved
- `/workers/findings/[findingId]`: planned finding decision route for approving one concrete workflow
- `/workers/loops`: planned finding-filtered workflow catalog; not an always-on queue in Crawl
- `/workers/runs`: planned doctor-pass and approved-workflow run history; no queue controls in Crawl
- `/workers/privacy`: planned local-execution and sync-boundary controls for runner revocation and report deletion
- `/starter/generate-codebase/review`: customer-facing `Review` handoff; it makes one auto-download attempt for the Ship by Sunday Codebase, then keeps the fallback download link visible if the browser blocks the download
- `/starter/lessons`: protected Tutorial Videos index inside Starter
- `/starter/lessons/[lessonKey]`: protected video-first tutorial watch page; uses the same lesson video content as the post-review lesson flow without generated-codebase unlock or progress state
- `/settings`: protected account and product settings
- `/lesson/[lessonKey]`: canonical post-review lesson route; renders locked messaging before unlock and video-first lessons after unlock

## Protected compatibility routes

- `/generate-codebase`: compatibility redirect to `/starter/generate-codebase`
- `/generate-codebase/review`: compatibility redirect to `/starter/generate-codebase/review`
- `/tutorials`: compatibility redirect to `/starter/lessons`
- `/tutorials/[lessonKey]`: compatibility redirect to `/starter/lessons/[lessonKey]`
- `/execute`: compatibility route for old Execute / Ship links; before post-review unlock it redirects to `/starter/generate-codebase/review`, and after unlock it redirects to the canonical Build Lessons destination
- `/mission`: compatibility route for old bonus-library links; before post-review unlock it renders Review guidance, and after unlock it redirects to the Review Lesson Map at `/starter/generate-codebase/review?showLessonMap=1`
- `/artifacts`: legacy compatibility route that now forwards into `/starter/generate-codebase/review`
- `/start`: compatibility redirect to `/starter/generate-codebase`
- `/product`, `/product/[stepId]`, `/design`, `/design/[stepId]`, `/marketing`, `/marketing/[stepId]`, `/build-plan`, `/build-plan/[stepId]`: compatibility redirects to the matching `/starter/generate-codebase#<section>` anchor; `/marketing/operating-system` redirects to `/starter/generate-codebase#generated-preview`

Repeat-routing note: `/execute` does not render a bridge page. Review owns the post-download continue action, `/execute` preserves old links by sending unlocked members into Build Lessons, and `/mission` preserves old library links by sending unlocked members into the Review Lesson Map.

These protected routes render behind `src/app/(app)/layout.tsx`, starting from server-fetched access or codebase-workspace data before the browser resumes live Convex subscriptions. The canonical paid intake is offer-specific now: Starter checkout lands in `/starter/home`, Workers checkout lands in `/workers/setup`, and `/home` remains the protected recovery hub.

## Integration routes

- `POST /api/stripe/checkout`: creates hosted Stripe Checkout Sessions for Starter and Workers
- `POST /api/stripe/checkout/express`: creates custom-ui Checkout Sessions for Express Checkout
- `POST /api/stripe/webhook`: verifies Stripe webhook signatures at the app origin and synchronizes Starter and Workers billing state into Convex through the trusted billing boundary
- `POST /api/observability/clerk`: verifies Clerk webhooks for observability
- `POST /api/observability/vercel`: verifies Vercel deployment webhooks for observability

## Why this matters

If you use the wrong route language in prompts or docs, the agent can implement the right idea against the wrong surface.
