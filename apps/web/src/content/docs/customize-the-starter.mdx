# Customize the Starter

These are the intended extension points for the starter. Change these first instead of scattering one-off edits across the repo.

## Best first changes

| Area                   | What to change first                                                                                                                        | Verification    |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | --------------- |
| Product config         | Name, promise, price, brand defaults, route constants, and public CTA defaults in `src/config/product.ts`                                   | `bun run build` |
| Module flags           | `starterConfig.modules` plus the neutral workspace-home fallback                                                                            | `bun run build` |
| Marketing site         | Man Meets AI index copy plus the Starter and Workers sales pages                                                                            | `bun run build` |
| Public blog surface    | Blog CTA target in `src/config/product.ts`, editorial copy in `src/app/(marketing)/blog/_content/blog.ts`, and posts in `src/content/blog/` | `bun run build` |
| Protected workspace    | Mission framing, lesson chrome, artifacts, and settings surfaces                                                                            | `bun run check` |
| Theme and styling      | Colors, typography, spacing, imagery, and motion defaults                                                                                   | `bun run build` |
| Optional build helpers | Codebase handoff CTA and Codex-assisted build helpers                                                                                       | targeted checks |

## Good first milestone

A strong early milestone is:

1. the public landing page is rewritten
2. the protected app reflects your product language
3. the first real protected user flow is visible
4. the paid-access contract still works

If you are not keeping the guided course, the first real protected Starter flow should now be the codebase-first app surface on `/starter/generate-codebase`, not a dead-end disabled shell.

## Leave these alone until later

Do not start by rewriting:

- checkout creation
- webhook handling
- access grants
- success-page recovery logic

Those are the highest-risk parts of the starter.

## Safeguards

- keep `src/config/product.ts` as the first place to change product identity and route constants
- keep `/`, `/starter`, and `/workers` as separate public surfaces instead of rebuilding one giant sales page
- keep the public blog route in `src/app/(marketing)/blog/[[...slug]]/page.tsx`, the editorial UI in `src/app/(marketing)/blog/_components/**`, route helpers in `src/app/(marketing)/blog/_lib/**`, and article source files in `src/content/blog/**`
- use `starterConfig.modules` before inventing route-level hacks or manual hidden links
- keep public offer work inside `src/app/(marketing)/page.tsx`, `src/app/(marketing)/starter/page.tsx`, `src/app/(marketing)/workers/page.tsx`, `src/components/layout/public-site-header.tsx`, and `public/`
- keep shared course contracts inside `src/lib/course/**` and route-facing course UI inside `src/app/(app)/_components/course/**`
- keep starter-mode protected home work inside `src/app/(app)/_components/workspace-home/**` and `src/app/(app)/_lib/workspace-home-model.ts`
- keep the access layer as the source of truth for product access
- keep the purchase-to-access behavior aligned with the verified checkout and webhook contract

## Starter mode

The starter now has a deliberate `course = false` mode.

When `starterConfig.modules.course` is `false`:

- `/starter/generate-codebase` is the first protected app surface
- `/product`, `/design`, `/marketing`, and `/build-plan` stay as stable stage-entry routes but redirect into nested codebase pages
- `/mission` and `/lesson/[lessonKey]` become the optional post-review bonus library after unlock, while `/artifacts` remains a compatibility forward into `/starter/generate-codebase/review`
- the paid-access and access-recovery contract stays unchanged

That is the preferred way to move toward a non-course product. Do not start by renaming routes or rewriting the access stack.

## What success looks like

You are customizing cleanly when the starter feels like your product before you have touched the fragile auth and billing path.

For the homepage specifically, clean customization now means:

- `/` stays the Man Meets AI brand and routing page
- `/starter` owns the Starter checkout CTA with offer id `starter`
- `/workers` owns the Workers checkout CTA with offer id `workers`
- the brand home link routes to `/`, and public navigation links Starter, Workers, Seal Team 6, Blog, and Sign in

If the homepage is part of the change, use [Configure the Homepage](/docs/configure-the-homepage) as the detailed source of truth instead of prompting from memory.
